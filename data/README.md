# Data

Nothing in `data/raw/` or `data/processed/` is committed to Git.
Only `data/splits/` and `data/reference/` are versioned.

## Folder layout

```
data/
├── raw/
│   ├── renders/        Kaggle render dataset (unzipped, unchanged)
│   ├── photos/         our own photos, one subfolder per session
│   ├── labels/         CVAT exports for our photos
│   └── rebrickable/    Rebrickable CSV downloads
├── processed/          anything generated by our code (crops, resized images)
├── splits/             versioned: which photo is in which split
└── reference/          versioned: small hand-made tables (measured colours)
```

Rule: `raw/` is never edited by hand or by code. Everything derived goes
into `processed/` and must be reproducible from `raw/` with a script.

## 1. Renders (training data)

Source: [Images of LEGO Bricks](https://www.kaggle.com/datasets/joosthazelzet/lego-brick-images)
by J. Hazelzet (40,000 images, 50 part types).

**Option A: Kaggle CLI**

1. Create an API token on kaggle.com → Settings → API → *Create New Token*
2. Put the downloaded `kaggle.json` into `~/.kaggle/`
   (Windows: `C:\Users\<you>\.kaggle\`)
3. Run from the repo root:

```bash
pip install kaggle
kaggle datasets download -d joosthazelzet/lego-brick-images -p data/raw/renders --unzip
```

**Option B: manual**
Download the ZIP from the Kaggle page and unzip it into `data/raw/renders/`.

**On Kaggle Notebooks** nothing needs downloading: add the dataset via
*Add Input*, it appears under `/kaggle/input/`.

## 2. Our photos (fine-tuning and test)

Stored in our private Kaggle dataset `<name-tbd>`. Download the same way
into `data/raw/photos/`.

Each capture session gets its own folder:

```
photos/
├── 2026-11-04_s01/
│   ├── IMG_0001.jpg
│   └── ...
└── photos.csv
```

`photos.csv` has one row per photo:

| column | example | meaning |
|---|---|---|
| `file` | `2026-11-04_s01/IMG_0001.jpg` | path relative to `photos/` |
| `session` | `s01` | capture session |
| `camera` | `pixel7` | device used |
| `light` | `2xLED` | lighting setup |
| `n_bricks` | `6` | number of bricks in the photo |
| `layout` | `separated` | `separated` or `pile` |

Adding new photos: create a new session folder, add rows to `photos.csv`,
upload a new version of the Kaggle dataset. Never rename or delete
existing photos, the splits refer to them by path.

## 3. Rebrickable

Download from https://rebrickable.com/downloads/ into `data/raw/rebrickable/`:
`colors.csv`, `parts.csv`, `sets.csv`, `inventories.csv`, `inventory_parts.csv`.

## Splits

`data/splits/finetune.csv` and `data/splits/test.csv` list photo paths.

- Splits are made **by session**, never by single photo. Photos from the
  same session (same bricks, same light) must not end up in both splits.
- `test.csv` is frozen once created. Never train, fine-tune or tune
  thresholds on it. Changes only after a team decision in `#decisions`.

## Paths in code

Code reads the data location from the environment variable
`LEGOREC_DATA`, defaulting to `data/`. On Kaggle set it to the input folder:

```python
import os

os.environ["LEGOREC_DATA"] = "/kaggle/input"
```
